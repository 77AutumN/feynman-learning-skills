# 收口成册

只有用户明确说“懂了、收口、整理笔记、做成卡片”等才加载本文件。普通“继续”不进入这里。

## 1. 锁定这一节

从系列 `index.md` 读取当前 episode ID、一个核心问题、本节范围、不展开项和下一入口。成册全程沿用该 ID；不扫描目录计算新编号，也不自动开始下一节。

若这次对话不是学习过程，而是写代码、调实验或闲聊，先确认用户是否仍要把它整理为本系列的一集。

## 2. 收集真实材料

按需读取：

- 当前会话中已经讲清的内容与可用摘要；
- 当前 `index.md` 和本节来源；
- `figures/` 中属于本节的可视化；
- 用户主动暴露的卡点、明确存疑与啊哈；
- 本节代码、命令和实测数字。

把讲解方选错结构和解释错误留在生产记录中。用户错误原话只作为明确标注的历史作答记录出现在自测，随后紧跟批改；知识卡与自测的正式答案、精髓只呈现核实后的正确机制与边界。讲解方的问题不能变成用户薄弱项。

## 3. 先写视觉导演单

复制 `../templates/visual-brief.md` 为：

`<系列目录>/cards/NN-visual-brief.md`

用它钉住知识边界、真实卡点、术语与公式、变化对象、隐喻边界、每张卡的因果分工和验收问题。优先由 agent 选择准确的视觉表达；只有候选隐喻可能造成实质技术误导时才询问用户。

按 `card-production.md` 的“视觉底座”记录随包 `v0` 基线；本文件只规定先写导演单的时序。

## 4. 生成两类复习产物

知识卡按 `card-production.md` 生成。

《费曼自测》复制 `../templates/feynman-selftest.md`，保存为：

`<系列目录>/NN-<title-slug>.md`

每题写：

`题目 → 用户原话作答 → 批改 → 正确精髓一句话`

优先使用学习时真实出现的问题，保留用户原话和原意；没答出就如实记录。错误作答紧跟明确批改，正式答案与精髓必须正确。未作答就写“未作答”，附参考答案，不编造回答，也不将跳过的小问题记为薄弱项。批改只补足或订正，不美化；末尾只列用户实际暴露的薄弱项。合成示例须标为“演示作答”，不进入当前用户的学习记录。

## 5. 渲染、检查、保存证据

按 `card-production.md` 渲染并逐张检查。只有实际产物通过后，才把以下结果写回视觉导演单的“渲染后验收记录”：

- 正式文件与数量；
- 当前有效批次的 manifest identity 与 validator 结果；逐文件 bytes、哈希和尺寸明细留在 manifest，不在导演单复制；
- 逐张原尺寸与贴图页的人工阅读结果，以及动态可视化结果或不需要动态的理由；
- 当前遗留问题与人工发现；返修时旧批次只记录失效原因，新批次通过后再记录为当前有效批次。

若用户复检发现概念、术语、公式或可读性问题，立即标记旧的“已通过”证据失效；沿用同一个 episode 和导演单追加返修记录，然后重新渲染与检查。

## 6. 最后更新索引

确认真实理解确认、自测、已验收卡片及导演单证据均已保存后，才更新 `index.md`：

1. 追加卡片、自测和导演单链接；
2. 把本 episode 标为 `已闭环`；
3. 写清下一入口；
4. 若确有下一节，此时才分配新的 episode ID，并置为 `待学`。

任一步失败、中断或缺少真实理解确认，当前 episode 保持 `学习中`，不推进指针；仍可在索引链接已经生成的产物并写清待补证据。演示或验证应标为演示，不把模拟对话或复制历史回答记成真人理解确认。

## 7. 停下

最终只报告本集产物、验收结果和下一入口。提醒用户可以亲自复核概念，但不要求复述；不自动继续教学、发布、提交 Git 或把私人存档改写成公开帖。
