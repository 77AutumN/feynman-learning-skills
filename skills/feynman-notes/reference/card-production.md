## 内容边界

卡片是给未来的自己复习的正确版本，不是聊天记录。

- 只呈现已经核实的机制、数字、源码和边界。
- 用户真实问题决定讲解顺序，但错误原话、订正过程和讲解方错误只留在视觉导演单。
- 每张机制卡只回答一个因果问题；卡组停在本节边界，不提前讲下一节。
- 学习时形成的有效可视化必须进入分镜，并保留它真正表达机制的对象、数值、路径或状态。

## 卡组叙事

常用骨架是：

`问题 → 机制起点 → 关键变化 / 因果接力 → 结果 → 正确边界 → 小结 → 下一入口`

使用**零上下文入口**：第一张内页先让真实对象、来源和动作可见，再贴技术名称；不能用尚未解释的术语直接开场。开场段通常用 3–5 张卡走完 `起点 → 任务 → 组织 / 变化 → 结果`；短卡组可以收窄张数，但仍要形成闭合因果链。

按机制增删，不为凑固定张数添加卡。封面、小结和卡点卡可以以文字为主；机制卡的主视觉必须独立承担解释工作。

## 视觉底座

- 本公开版使用随包的暖白 / sage 视觉基线 `v0`，无需外部视觉策略文件。
- 逻辑画布 `1080×1440`，2× 渲染为 `2160×2880` PNG。
- 暖白底 `#FAF8F3`，sage `#7E8B6D` 为主调，terracotta `#b06a5a` 表示反例或负值，框线 `#e7e1d6`。
- 正文使用无衬线字体；公式与数字使用等宽字体。
- 封面默认用 `#F4F3EF` 素底、思源黑 Heavy 的 2–3 行 wordmark、末行红色 `#D63A2F` 单线和底部小灰字。标题是术语时，加一句零基础副标题。只有封面使用 bold 皮肤。
- 字体位于本技能的 `assets/fonts/notosanssc.ttf`，校验 schema 也随技能分发；无需依赖个人工作区。
- 导演单记录 `v0` 基线与当前卡组的视觉选择；技术事实、术语解释、可读性和验收标准以本文件为准。

视觉应像干净的技术教学图，不使用营销金句、互动钩子或人设落款。

## 让机制可见

机制卡至少让人看见一种变化：

- 对象被创建；
- 参数或数值从前值变到后值；
- 信息沿真实路径移动；
- 多个状态形成因果接力。

遮住标题和正文后，主视觉仍应能辨认“什么对象、发生了什么、处在哪个阶段”。连续卡追踪同一对象时，固定它的位置、名字和视觉编码。

动态过程压成静态卡时，用前后关键帧、刻度差、轨迹残影或连续状态保留变化。只画一排框、装饰箭头、高亮或颜色切换，不能代替机制证据。

生活或机械隐喻必须贴合本节的角色和顺序。图中标 `教学示意`，导演单写清映射边界；进入隐喻承载不了的源码、公式或数值后，主视觉回到真实技术对象。不要默认继承上一集的工厂、机台或流水线皮肤。

## 术语公式与源码

- 新术语首次出现时，在同一张卡、同一阅读视线说明“它是什么、在这里做什么”。后续继续用“人话标签（术语）”。
- 缩写、变量下标、希腊字母、运算符和专有中文名都计入术语。普通机制卡最多引入 2 个新术语；专门的术语桥接卡可以更多，但要逐项解释。
- 每条公式紧跟动作句：谁拿什么，做什么，得到什么。符号表不能代替动作句。
- 只有本节触发源码锚定时，才在卡中把真实源码、人话动作和同一对象的前后状态放在一条阅读路径上。

## 使用现有渲染器

新系列且 `cards/render_cards.py` 不存在时，复制本技能的 `templates/render_cards.py`。既有系列扩展现有生成器，保留全部 episode builders；不要用模板覆盖它，也不要顺手迁移渲染器架构。

实现优先级为：随包 `v0` 基线与现有布局 helper → 当前 episode builder 内的小组合 → 两个独立系列出现同一布局需求后再抽共享 helper。单集需求留在当前 builder 中。

渲染器可从公开仓库的 `skills/feynman-notes/`、工作区的 `.agents/skills/` 或 `.codex/skills/` 以及用户安装位置找到技能资源。自动发现失败时，设置 `FEYNMAN_NOTES_SKILL_DIR` 为完整的 `feynman-notes` 目录；`FEYNMAN_NOTES_WORKSPACE_ROOT` 只用于产物的工作区相对路径根。

修改前先定位并读取：

- 命令入口与 episode 注册表；
- 当前 episode builder；
- 它直接调用的 helper；
- 本次会触及的共享布局、预检和事务代码。

先运行当前系列渲染器的 `--help` 与 `--list`，以脚本当前行为为准，不在文档缓存命令细节。只改当前 builder 时回归当前 episode；改到共享代码时回归全部已注册 episode。

每次成功渲染同时生成 `NN-card-manifest.json`：记录系列、集数、主题、生成时间、批次 identity，以及按贴图页顺序排列的卡片文件 / SHA-256 / 尺寸和贴图页 SHA-256。只有进程返回 0 且输出 `DONE N/N PNG`，才进入人工验收。

已有 PNG / HTML 只需补 manifest 时运行 `--manifest-only <episode>`；只读检查运行 `--validate-manifest <episode>`。后者检查最小字段、文件顺序、PNG 哈希 / 尺寸和 gallery 哈希，不重渲染或改写产物。

## 逐张验收

### 内容与机制

- 每张卡的结论、数字、公式、源码与本节来源一致。
- 新术语在首现卡已讲人话，公式有动作句。
- 机制卡离开正文仍看得出对象、变化方向与阶段；非机制卡记 `N/A`。
- 隐喻未越过技术边界，教学映射已标记。
- 最终卡与自测的正式答案、精髓正确；自测中保留的错误原话明确标成历史作答并紧跟批改，讲解方错误只留在生产记录中。

### 文件与可读性

- 每张 PNG 可完整解码，尺寸为 `2160×2880`；贴图页中的相对链接全部存在。
- `NN-card-manifest.json` 结构完整；卡片顺序与贴图页一致，各 PNG 的哈希 / 尺寸和贴图页哈希均可复算。
- 运行生成器已有的 overflow、SVG viewBox、受控文字和 strict 预检。
- 受控框优先使用生成器现有的 `TFit`、`TWrap` 或 `BoxText`；达到最小字号仍放不下时拆内容，不靠缩字硬塞。
- 分别查看原尺寸和贴图页约 540px 的每一张卡。主结论无需放大即可读清；检查溢出、裁切、字体回退、贴框、遮挡与拥挤。
- 首次使用新布局或已有拥挤反馈时，先渲染 2–3 张高风险试片，再铺开全组；正式逐张验收仍要完成。
- 有动态可视化时，确认它表现真实变化、可重播且 reduced-motion 可读；没有时在导演单写 `N/A` 和理由。

把实际检查结果写回视觉导演单后，才能按 `closeout.md` 更新索引。不要自动发布或提交 Git。
