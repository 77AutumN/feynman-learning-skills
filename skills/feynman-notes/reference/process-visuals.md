# 带读过程可视化

只有文字、具体数字或小草图仍不足以让机制可见时，才加载本文件。过程可视化服务当场理解；正式知识卡另走 `card-production.md`。

## 先选图的职责

- **位置图**回答“我在哪，节点怎样相连”。多节点材料才需要；短问题用一行面包屑即可。
- **机制图**回答“哪个对象被什么动作改变”。它不能用抽象方框和装饰箭头冒充变化。

一张图只承担一种主要职责。全局地图是 `index.md` 的派生物，不保存独立进度。

## 最小教学原型

先让一个真实对象走完：

`起点 → 真实动作 → 可见结果`

优先用静态前后对照、数字轨迹、时间线或 ASCII 草图。确实需要交互时，再创建 HTML，并立即保存到：

`<系列目录>/figures/viz_NN_<slug>.html`

首次版本只保留一条主故事和必要控制。主角、输入与输出使用本节真实例子，不用需要二次解码的占位符。

## 让变化真的发生

动态至少呈现一种真实变化：

- 对象被创建；
- 参数或数值改变；
- 信息沿路径移动；
- 因果状态接力。

按钮切换静态说明、变色、高亮或淡入淡出本身不算机制动画。动画默认单次播放、可以重播、不无限循环；`prefers-reduced-motion` 下仍保留可读的静态结果。

如果动态不增加理解，用静态关键帧，并记录为什么不需要动画。

## 空间导航

材料跨多个认知小节，或用户明确要“先看全局 / 按关系 / 空间化”时：

1. 从材料标题、目录、关键图和结论提取少量“要解决的问题”节点。
2. 沿用系列索引的稳定节点 ID；边写清前置、组成、因果、对照、证据或应用。
3. 用一行或迷你图标出“上游 → 当前节点 → 下一邻接点”，立即放大当前问题。
4. 讲完后回到全图，只说明这次点亮了哪条关系。

来源没有说明的关系标为教学推断或欠条，不为了图形闭合把它画成事实。

## 追问驱动修改

用户能指出某个动作没画出来时，只补那个动作。用户仍觉得整张图抽象或没头没尾时，图的结构已经失败：回到一个更小的问题，换真实对象重做，不在旧图上继续堆框、标签和动画。

## 验证预算

过程 HTML 默认做一次桌面和一次手机 smoke check：

- 能正常渲染，无明显溢出或裁切；
- 核心控件可用，主结论无需猜；
- 动态与 reduced-motion 都能表达相同机制；
- 文字、形状或线型共同表达状态，不只依赖颜色。

首次原型不需要为了精致而扩展全断点、主题和动效矩阵。用户确认故事讲通或明确要求精修后，再增加美化或复杂交互。

整理知识卡时，保留这里真正表达机制的对象、数值、路径和关键帧；不要把它降级为通用方框图。
