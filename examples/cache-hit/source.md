# 为什么同一个输入第二次不用再算？

这是本仓库自写的教学材料，所有数值都是可复算的示例，不是外部系统的性能数据。

设有一个函数：收到整数 n，就计算 n × n。旁边放一本结果表，开始为空。每次请求先查表：如果已有 n 对应的答案，就直接返回；没有才计算，把结果存入表再返回。

第一次收到 3：表里没有 3，执行 3 × 3 得到 9，存成 {3: 9}，返回 9。

第二次收到 3：查到表里已有 9，直接返回，真正的乘法计算次数仍为 1。这次查到可复用结果叫 cache hit（缓存命中）。没有查到叫 cache miss（缓存未命中）。

收到 4：表里没有 4，所以计算 4 × 4 得到 16，再保存。输入相同且计算规则不变时，可以复用结果；输入不同，不能拿 3 的答案去回答 4。

这里还有一个成立条件：表里保存的结果必须仍适用于当前任务。如果函数从平方改成立方，旧表里的 {3: 9} 就过时了。需要清掉旧结果，或让计算规则的版本参与查表的键，不能把“查到了”当成“仍然正确”。

本节只讲复用怎样跳过重复计算。不展开淘汰策略、容量、并发或真实服务的响应时间。

运行旁边的 `source.py` 可以验证计算次数和更换规则后的行为。程序中的计数表示实际调用计算函数的次数，不是耗时测量。
